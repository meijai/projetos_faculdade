1. O que é o projeto?

Desenvolvimento de um mini-ORM construído do zero com PHP 8 e PDO/MySQL, sem bibliotecas ou frameworks externos.

  • Finalidade: Persistir e gerenciar entidades de livros e autores de uma biblioteca universitária.
  • Foco avaliativo: Aplicação prática dos conceitos de Orientação a Objetos integrados ao banco de dados relacional.

2. Como organizamos o código

Adoção do padrão Data Mapper com divisão estrita em duas camadas:

📦 Domínio (src/Domain/)

  • Classes Livro e Autor
  • Cuidam apenas dos dados e regras de negócio
  • Zero comandos SQL e zero acoplamento a banco

⚙️ Infraestrutura (src/Infrastructure/)

  • AbstractRepository, LivroRepository, AutorRepository
  • Fábrica de conexões PDO (Conexao)
  • Únicos responsáveis por comandos SQL e persistência

3. Conceitos de POO Aplicados

🔒 Encapsulamento

Propriedades privadas, validações nos construtores e proteção de identidade: o id é imutável após gravado via atribuirId().

🏛️ Abstração & Herança

AbstractRepository concentra a lógica comum do CRUD. As classes filhas apenas especializam a tabela, colunas e hidratação.

🔄 Polimorfismo

A interface RepositoryInterface padroniza o contrato de operações, permitindo manipular qualquer repositório de forma uniforme.

🔗 Relacionamento N:N

Vínculo via tabela associativa livros_autores e reconstrução de coleção no objeto Livro sem duplicatas em memória.

4. Como o ORM salva os dados

  • Decisão inteligente em salvar():
    • Se o objeto não possui ID (null): executa INSERT parametrizado e atualiza a identidade com lastInsertId().
    • Se o objeto já possui ID: executa automaticamente um UPDATE.
  • Segurança: 100% das consultas utilizam Prepared Statements do PDO contra SQL Injection.
  • Transações ACID: Operações de múltiplos passos usam beginTransaction() e rollBack() em caso de falha de chave estrangeira.

6. Dificuldades Encontradas

⚠️ Mapeamento e Reconstrução da Relação N:N

Sincronizar a tabela associativa livros_autores com a coleção em memória, garantindo que os autores fossem carregados sem duplicar instâncias de objetos no mesmo livro.

⚠️ Tratamento de Transações e Integridade Referencial

Configurar corretamente o controle transacional com PDO (beginTransaction e rollBack) para capturar exceções de Foreign Key e garantir que dados inconsistentes não persistam no banco.

⚠️ Generalização do CRUD no AbstractRepository

Construir um método salvar() genérico capaz de decidir dinamicamente entre INSERT e UPDATE com base no estado do identificador, mantendo o SQL 100% parametrizado.
