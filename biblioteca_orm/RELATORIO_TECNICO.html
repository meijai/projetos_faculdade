Atividade: Avaliação Prática — ORM com PHP Puro e MySQL

1. Objetivo do Sistema

Desenvolvimento de uma camada própria de persistência (mini-ORM) em PHP 8 puro e MySQL, sem uso de frameworks externos, demonstrando na prática os conceitos fundamentais de Orientação a Objetos e o padrão arquitetural Data Mapper.

2. Decisões Arquiteturais

2.1 Separação em Camadas (Data Mapper)

  • Domínio (src/Domain/): classes Livro e Autor. Guardam apenas dados, regras de negócio e validações, sem nenhum acoplamento a SQL ou conexões de banco de dados.
  • Infraestrutura (src/Infrastructure/): repositórios (AbstractRepository, LivroRepository, AutorRepository), contrato (RepositoryInterface) e conexão PDO (Conexao). Centralizam todo o acesso ao MySQL.

2.2 Aplicação dos Pilares de POO

  1. Encapsulamento: todas as propriedades das entidades são privadas. Métodos de acesso expõem apenas o necessário (titulo(), nome()). O id só pode ser atribuído uma única vez após gravação via atribuirId(); se houver tentativa de alterá-lo, o sistema dispara uma exceção LogicException.
  2. Abstração e Herança: a classe abstrata AbstractRepository implementa o CRUD reutilizável (buscar, listar, salvar, excluir). As classes filhas (LivroRepository e AutorRepository) apenas especializam o nome da tabela, lista de colunas e a conversão entre registro do banco e objeto real.
  3. Polimorfismo: a interface RepositoryInterface padroniza o contrato de operações, permitindo que rotinas externas operem sobre qualquer repositório de forma agnóstica à classe concreta.
  4. Relacionamento N:N: o vínculo entre livros e autores é persistido na tabela associativa livros_autores. O método Livro::adicionarAutor() impede autores duplicados na lista em memória.
  5. Segurança e Transações: 100% das consultas utilizam Prepared Statements do PDO com parâmetros nomeados. Operações de múltiplos passos utilizam transações com rollBack() caso ocorra falha de integridade referencial.

5. Limitações Conhecidas

  1. Ausência de Lazy Loading: o carregamento dos autores vinculados a um livro é explícito via método do repositório, sem proxies automáticos.
  2. Inexistência de Identity Map: buscas repetidas pelo mesmo ID geram instâncias separadas na memória.
  3. Sem Unit of Work: operações no banco de dados são disparadas imediatamente a cada chamada de salvar() ou excluir().
